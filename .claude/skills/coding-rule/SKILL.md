# Python 코딩 표준 (VishasBody)

공통 원칙은 `visha-common:coding-common-rule`, 확인 절차는 `simple-test`, 테스트 작성은 `qa-test`를 따른다. 이 스킬은 이 프로젝트에만 해당하는 것을 담는다.

## 0. 기준
- 구현 기준은 기술 명세(`docs/tech_spec/`) 하나다. 노션은 메인 스레드가 명세로 정리한다.
- 서버 규약(시그니처, 등록, 메시지 헤더, 에러·종료 코드)은 명세 머리말의 "참조 규약" 경로를 GitHub에서 읽는다(`gh api repos/Vishamos/VishaSynapse/contents/<path>`). 스킬·기억·README 요약에 의존하지 않는다.
- 이 스킬과 어긋나는 작업(예: 기존 파일을 통째로 다시 쓰기)이 필요하면 하기 전에 "규칙 예외 제안"으로 알린다.

## 1. 분석
- 대상 파일을 끝까지 읽고 Grep으로 사용처(`import`, 호출부)를 찾아 영향 범위를 확인한다.

## 2. 런타임과 의존성
- Python 3.12 기준(mediapipe 지원 버전). 표준 라이브러리를 우선한다(`struct`, `threading`, `queue`, `unittest`).
- 새 의존성 추가는 사용자 승인이 필요하다. 추가하면 `requirements.txt`와 README "환경"에 버전과 함께 적는다.
- 의존성 점검 명령(security용): 없음. 점검 도구(`pip-audit`)가 설치되어 있지 않다(설치는 사용자 승인 필요). security는 "의존성 점검 명령 없음"으로 보고하고 `requirements.txt`의 패키지 목록만 확인한다.
- 모델 파일(`*.task`, `*.onnx`)은 커밋하지 않는다(`.gitignore`). 새 모델을 쓰면 README "실행 방법"에 내려받는 주소(ONNX는 변환 방법)를 추가한다.

## 3. 프레임 루프
- 메인 루프(카메라 → 추론 → 그리기)에서 블로킹 I/O를 하지 않는다. 네트워크 송신은 별도 스레드에서 하고, 메인 루프는 최신 프레임 데이터만 넘긴다(크기 1 큐 또는 최신값 덮어쓰기). 밀린 프레임은 보내지 않고 버린다(실시간 데이터).
- 프레임마다 도는 새 작업은 비용(ms)을 추정해 보고에 적는다. `stats.py`의 단계별 시간에 넣을 수 있으면 넣는다.
- 스레드 간 공유 상태는 `threading.Lock` 또는 `queue.Queue`로만 주고받는다. (C#의 `lock` / `ConcurrentQueue`에 해당)
- 종료 시 스레드를 정리한다: 종료 이벤트(`threading.Event`) 설정 → 소켓 닫기 → `join(timeout)`.

## 4. 바이너리 패킹
- `struct` 형식 문자열은 항상 `<`(리틀 엔디언, 패딩 없음)로 시작한다. 형식 문자열과 크기(`struct.calcsize`)는 모듈 상수로 한 번만 정의한다.
- 프로토콜 값(시그니처, 메시지 종류 번호, 버전, flags 비트)은 상수로 정의해 쓰고 숫자를 직접 적지 않는다.
- 패킷은 고정 크기다. 검출되지 않은 부위는 flags 비트로 표시하고 값은 0으로 채운다.
- 바이트 배치 자체는 이 스킬에 적지 않는다. 기준은 기술 명세다. 배치를 바꾸면 `docs/protocol/README.md`도 함께 고친다.

## 5. WebSocket 송신
- 접속 직후 등록을 보내고 `client.registered`를 받은 뒤에만 바이너리를 보낸다. 등록 전 데이터는 버린다.
- 끊기면(예외·close) 일정 간격으로 다시 접속하고 다시 등록한다. 재접속 대기 중에도 트래킹은 계속 돈다.
- 서버 ping에 pong이 자동 응답되는지, 쓰는 라이브러리 기준으로 확인해 보고에 적는다.
- 에러는 예외 종류와 종료 코드만 로그에 남긴다. 받은 메시지를 프레임마다 출력하지 않는다.

## 6. 비밀 값
- 서버 주소는 코드에 하드코딩하지 않는다. `config/config.local.json`(git 제외) 또는 명령줄 인자로 받는다.
- 서버 주소를 로그·화면에 출력하지 않는다.

## 7. 스타일
- 기존 파일의 들여쓰기, 명명 방식(snake_case 함수, PascalCase 클래스), 줄바꿈(CRLF)을 유지한다. Edit로 수정한다.
- 주석은 한국어로, "왜 그렇게 했는지"가 코드만으로 드러나지 않을 때만 단다.
- `src/legacy/pose_test.py`는 비교용 보관본이라 고치지 않는다.

## 8. 보고에 더할 것
developer 보고 형식에 다음을 더한다.
- **흐름 대응표**: `함수(파일:줄) → 명세 § → 확인 방법과 결과`. 낯선 Python 개념은 C# 대응을 짧게 붙인다.
- **프레임 예산**: 프레임마다 추가된 작업의 추정 비용.
- **사용자가 확인할 것**: 실제 웹캠·서버 연동(이 PC에는 카메라가 없을 수 있다).
- **문서 반영 내용**: 명세 "구현 현황"에 넣을 줄, README에 반영할 결정·측정값(메인 스레드가 반영).
