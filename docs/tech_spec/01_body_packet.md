## 5. 루트 위치
몸 좌표(4.6)는 원점이 골반이라 사람이 카메라 앞에서 움직여도 값이 변하지 않는다. 아바타 위치를 움직이기 위해 **카메라 기준 골반 중심 위치**를 따로 보낸다.

| 번호 | 내용 | 구분 | 근거 |
|---|---|---|---|
| 5.1 | 계산: **몸통 점(얼굴·어깨 0∼12, 골반 23·24)** 중 화면 좌표 visibility 0.5 이상인 점마다 "월드 좌표 점을 t만큼 옮겨 카메라로 투영하면 그 점의 화면 좌표에 온다"는 식 2개(가로·세로)를 세우고, 최소제곱으로 t = (tx, ty, tz)를 구한다. 식: `f·tx − (u−cx)·tz = (u−cx)·Z − f·X`, `f·ty − (v−cy)·tz = (v−cy)·Z − f·Y` (u, v: 픽셀, X, Y, Z: 월드 좌표, MediaPipe 축) | 확정(사용자 답변, 2026-11-23) | 기획 없음(사용자 요청). MediaPipe 월드 좌표 축은 카메라와 나란하므로 모르는 값은 t뿐. 어깨너비 비율 방식과 달리 몸을 옆으로 틀어도 영향이 작고 x·y·z가 한 번에 나옴. 팔(13∼22)은 2026-11-23 실측 후 뺌: 카메라 쪽으로 뻗은 팔의 깊이 추정이 틀려 1.4m에서 z가 −1.1∼−1.2 → −1.3∼−1.5로 끌려감 |
| 5.2 | 점이 4개 미만이거나 결과 tz ≤ 0(카메라 뒤)이면 유효하지 않음: flags bit3 = 0, 값 0 | 확정(사용자 답변, 2026-11-23) | 식 수에 비해 점이 너무 적으면 값이 크게 튐 |
| 5.3 | 초점거리 f(픽셀) = (프레임 대각선 픽셀 / 2) / tan(화각 / 2). 화각은 `config.local.json`의 `camera_fov_deg`(**실제로 받는 프레임의 대각선 화각**, 도). 없으면 72 | 확정(사용자 답변, 2026-11-23) | 실행 PC 웹캠 RPC-20F 스펙 화각 72°(대각선으로 해석). 해상도를 지정하지 않아 4:3으로 잘려 들어올 수 있으므로 5.6 보정으로 맞춤 |
| 5.4 | 좌표: 카메라 기준 원시값(미터)에 4.8과 같은 Unity 변환 (−tx, −ty, −tz). 시작 위치를 0으로 맞추는 보정은 받는 쪽이 한다 | 확정(사용자 답변, 2026-11-23) | 트래커는 측정값만 보내고 아바타 배치 기준은 받는 쪽이 정함 |
| 5.5 | 디버그 화면 패널에 루트 위치 x, y, z(m)를 숫자로 표시. 스무딩은 넣지 않고, 흔들림을 본 뒤 1.5와 함께 정한다 | 확정(사용자 답변, 2026-11-23) | 보정·흔들림 확인용. 영상이 아니라 숫자라 2.1에 걸리지 않음 |
| 5.6 | 보정: 실행 PC에서 골반이 카메라에서 1.5m(줄자)인 자세로 표시된 z를 읽고, 다르면 `camera_fov_deg`를 고친다 | 확정(사용자 답변, 2026-11-23) | 거리는 f에 비례하므로 한 번 재면 화각을 역산할 수 있음 |
| 5.7 | 한계: 월드 좌표의 몸 크기는 평균 체형 기준 추정이라 절대 거리에 체형만큼 오차. 반신만 보여 점이 적으면 정확도가 떨어짐 | 해석 | MediaPipe 월드 좌표의 성질 |

비용: 점 25개 이하의 3미지수 최소제곱이라 프레임당 0.1ms 미만(1.2).
